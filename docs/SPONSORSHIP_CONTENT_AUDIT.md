## UX specification (proposal only)

This proposal is limited to the sponsorship benefits experience. It does not authorize implementation or changes to other site sections.

### Information hierarchy

1. Keep the BJLJ title and existing tier selector.
2. Group benefit rows under the three requested phases: TRƯỚC CHUYẾN ĐI, TRONG CHUYẾN ĐI and SAU CHUYẾN ĐI.
3. Within each phase, preserve the source’s channel and benefit group labels as subordinate headings where they help users scan.
4. Show every approved benefit’s tier value, quantity/specification, delivery timing and condition together.
5. Keep unresolved entries out of final sponsor-facing copy until their decisions are approved.

### Desktop table

- Use one comparison table per phase. Columns: benefit, the ten existing tier values, delivery timing and conditions.
- Retain the current POET typography, table colors, borders and spacing. Highlight the currently selected tier using the existing selection state.
- Keep the benefit column and tier header visible while the table scrolls horizontally. Constrain overflow to the table region; do not create page-level horizontal scrolling.
- Render exact quantities in cells (for example “2 vé”, “5m2”, or “1 video 30s”), not generic checkmarks.
- Keep any existing tier-tab, range-slider and expand/collapse behavior unless it conflicts with the approved phase grouping.

### Mobile table behavior

- Keep the existing tier selector usable at narrow widths and show a selected-tier benefit list by phase so long descriptions, quantities and conditions wrap without clipping.
- Provide clear phase headings and accessible phase navigation. If the all-tier matrix remains available, contain its horizontal scrolling within the table and keep the benefit label visible; do not shrink the text to fit ten columns.
- Ensure keyboard and touch users can change tiers and phases. Preserve visible focus and current expanded/collapsed behavior.

### Phase navigation and tier comparison

- Use three visible phase links or tabs that jump to or reveal the matching phase. Keep headings in the document and provide a clear active state.
- On desktop, show all ten tier columns so sponsors can compare them; the existing selected-tier interaction can highlight a column and continue to drive the selected-tier details.
- On mobile, default to the existing single-tier selection model. A side-by-side all-tier view can remain available in an internally scrollable table if usability checks confirm it works.

### FUND FOR FUN visual reuse (future task only)

- Use the same font family, brand colors, table header treatment, borders, spacing rhythm, phase headings and selected-tier feedback as BJLJ.
- Its three tiers need only three comparison columns; retain its own category names, exact values, quantities and timeline notes.
- Do not force a BJLJ tier crosswalk. The sources define no equivalence between the programs.
